Databases

The database question is worth a large share of the practical marks and follows a predictable shape: import the data, set the field types, build a form, run queries, and produce a report. Precision matters - a single wrong data type or a missing label costs the mark.

Syllabus coverage: 18.1 Create a database structure · 18.2 Manipulate data · 18.3 Present data
18.1

Create a Database Structure

Importing data and setting up tables

  • Import data from existing files - including .csv and .txt - using the specified field names to create the tables.
  • Check after importing that every record has arrived and that no field has been split or merged incorrectly.
  • Use exactly the field names the question gives, including capitals and spacing.

Data types

Data typeHoldsExample
Text (alphanumeric)Letters, digits and symbols that are not calculated withName, address, telephone number, product code
Numeric - integerWhole numbers onlyQuantity in stock: 47
Numeric - decimalNumbers with a fractional partWeight: 2.75
Numeric - currencyMoney, with a currency symbol and normally two decimal placesPrice: $12.50
Date/timeDates and times, which can be sorted and calculated withDate of birth: 04/09/2010
Boolean/logicalOne of two values onlyMember? Yes/No

Sub-types and display formats you must be able to set

  • Numeric sub-types - percentage, and a specified number of decimal places.
  • Boolean/logical display format - yes/no, true/false or a checkbox.
  • Date/time display format - for example dd/mm/yyyy, or a long date showing the month name.
Classic trap: a telephone number is text, not numeric. Leading zeros would be lost in a numeric field, and no one ever adds two telephone numbers together.

Primary and foreign keys, and relationships

A primary key is a field whose value is unique to each record, so it identifies that record and no other. A foreign key is a field in one table that holds the value of the primary key of another table, creating the link between them.
  • Create and edit primary and foreign keys.
  • Create relationships between tables by joining the primary key of one table to the foreign key of another.
  • A primary key must be unique and must never be left empty.

Flat file and relational databases

Flat file databaseRelational database
StructureOne table holding all the dataSeveral linked tables, joined by keys
UsesSmall, simple sets of data - a club membership list, a personal address bookLarger systems where data is related - school, stock control, booking systems
AdvantagesSimple and quick to set up; easy for a beginner; needs no specialist knowledge; low costNo unnecessary duplication of data; less storage used; data only has to be updated in one place, so it stays consistent; better security, as access can be granted table by table; complex queries across tables are possible
DisadvantagesData is duplicated in many records, wasting space; an update must be made everywhere, so data easily becomes inconsistent; harder to query in complex ways; less secure, as a user sees the whole tableMore complex to design and set up; needs more expertise; specialist software is more expensive

Creating and using a data entry form

You must be able to create a data entry form including:

  • The specified fields - and no others
  • Appropriate font styles and sizes
  • Appropriate spacing between fields
  • Suitable character spacing of individual fields - each field wide enough for its longest entry
  • Sensible use of white space
  • Radio buttons, check boxes and drop down menus where the choice is limited

Characteristics of good form design

  • A clear title and, where needed, brief instructions.
  • Fields in a logical order, ideally matching the order on the source document, so entry is fast.
  • Clear labels for every field, with enough space so nothing is truncated.
  • Consistent fonts, sizes, colours and alignment throughout.
  • Enough white space that the form is not cramped and is easy to read.
  • Controls that limit the choice - drop-down lists, radio buttons for one choice from several, check boxes for yes/no - which speeds entry and removes typing errors.
  • Related fields grouped together, and only the data that is actually needed requested.
Check your understanding
A school stores learner details and the subjects each learner takes. Explain why a relational database is better than a flat file.
In a flat file the learner's name and address would be repeated for every subject they take, wasting storage and meaning an address change has to be made in many places - so the data easily becomes inconsistent. A relational database stores each learner once in one table, each subject once in another, and links them with a foreign key, so data is entered and updated only once.
Give three features of a well-designed data entry form.
Any three of: fields in a logical order matching the source document; clear labels with enough space so entries are not truncated; drop-down lists, radio buttons or check boxes to limit choices and prevent typing errors; consistent fonts and sizes; sensible use of white space so it is not cramped.
18.2

Manipulate Data

Performing calculations

  • Use arithmetic operations or numeric functions to perform calculations, including calculated fields (stored in a query or table) and calculated controls (worked out on a form or report).
  • Use formulae and functions to perform calculations at run time:
    • addition, subtraction, multiplication, division
    • sum, average, maximum, minimum, count
  • Calculating at run time means the result is always up to date, and it does not have to be stored - so it can never disagree with the data it came from.

Sorting data

  • Sort into ascending (A to Z, smallest first, earliest first) or descending order.
  • Sort on a single criterion, or on multiple criteria - the first field sorts the records, and the second sorts within each group of equal values.
  • Read the order of the criteria carefully: sorting by Surname then Forename is not the same as Forename then Surname.

Searching and selecting data with queries

  • Use a single criterion or multiple criteria to select subsets of data using a query.

Operators

Wildcards

  • * (or %) stands for any number of characters - LIKE "S*" finds every entry beginning with S.
  • ? (or _) stands for exactly one character - LIKE "?at" finds cat, bat and hat but not chat.
  • Wildcards are used with LIKE, never with =.
AND narrows, OR widens. If a query returns no records, check whether you used AND where the question meant OR. If it returns everything, check the opposite.
Check your understanding
Write the criteria to find members from Nairobi who joined before 01/01/2024.
Town = "Nairobi" AND JoinDate < 01/01/2024. Both conditions must be true, so AND is required - OR would return every member from Nairobi plus every member who joined early, wherever they live.
What does the criterion LIKE "*ton" find, and how does it differ from LIKE "?ton"?
LIKE "*ton" finds entries ending in "ton" with any number of characters before it - Brighton, Preston, ton. LIKE "?ton" requires exactly one character before "ton", so it would find Eton but not Brighton.
18.3

Present Data

Producing reports

  • Produce reports that display all the required data and labels in full - nothing truncated, no field showing ###, no label cut off.
  • Set report titles exactly as the question specifies.
  • Produce different output layouts, controlling the display of data and labels in tabular (records in rows, fields in columns) or columnar (one record per block, fields listed down the page) format.

Headers and footers in a database report

SectionWhere it appearsTypical contents
Report headerOnce, at the very start of the reportThe report title, a logo, the date it was produced
Page headerAt the top of every pageThe column headings / field labels
Page footerAt the bottom of every pagePage number, date
Report footerOnce, at the very end of the reportGrand totals, averages, counts
Common error: a grand total placed in the page footer prints on every page and is wrong. Totals for the whole report belong in the report footer.

Aligning and formatting the data

  • Align data and labels appropriately - right align numeric data and use decimal alignment so figures line up on the decimal point and can be compared at a glance.
  • Text is normally left aligned; labels should line up with the data they describe.
  • Control the display format of numeric data:
    • the number of decimal places
    • a currency symbol
    • percentage format
  • Keep formatting consistent across the whole report, and make sure fonts are large enough to read in print.
Check your understanding
Where should a grand total of all sales appear in a report, and why?
In the report footer, because that section prints once at the very end of the report. Putting it in the page footer would repeat it at the bottom of every page, which is incorrect.
Why should currency values be right or decimal aligned?
So that the decimal points and digits line up vertically, making the column easy to read and the values easy to compare. Left-aligned figures of different lengths are hard to compare and look unprofessional.
Databases checklist
  • I can import .csv and .txt data using specified field names.
  • I can set text, numeric (integer, decimal, currency), date/time and Boolean data types, with sub-types and display formats.
  • I can create primary and foreign keys and build relationships between tables.
  • I can compare flat file and relational databases and state the characteristics of good form design.
  • I can create a data entry form with radio buttons, check boxes and drop-down menus.
  • I can build calculated fields and controls, and use sum, average, maximum, minimum and count.
  • I can sort on single and multiple criteria, ascending and descending.
  • I can write queries using AND, OR, NOT, LIKE, >, <, =, >=, <=, <> and wildcards.
  • I can produce tabular and columnar reports with correct titles and report, page header and footer sections.
  • I can align and format numeric data with decimal places, currency symbols and percentages.
