Web Authoring

Website authoring is tested by writing the code yourself, not by using a design package. You need to know the three development layers, the HTML that builds the content layer, and the CSS that builds the presentation layer - and you must be able to explain why relative file paths are used.

Syllabus coverage: 21.1 Web development layers · 21.2 Create a web page · 21.3 Use stylesheets
21.1

Web Development Layers

The three layers

Content layer
  • Used to enter the content and create the structure of a web page
  • Written in HTML
  • Holds the text, images, tables and links - what the page says
Presentation layer
  • Used to display and format elements within a web page
  • Written in CSS
  • Holds the colours, fonts, sizes, spacing and borders - how the page looks
Behaviour layer
  • For a scripting language to control elements within a web page
  • Written in a scripting language such as JavaScript
  • Handles what happens when the user interacts - what the page does
Why separate the layers? The same content can be restyled by editing one stylesheet, one stylesheet can format an entire site consistently, the HTML stays short and readable, and the site is quicker to maintain.
21.2

Create a Web Page (HTML)

The head and body sections

Purpose of the head section
  • Holds information about the page, most of which the visitor never sees
  • The page title displayed in the browser tab
  • Links to external stylesheets
  • Metatags for the charset, description, keywords, author and viewport
  • A default target window for links
Purpose of the body section
  • Holds the content the visitor actually sees in the browser window
  • Headings, paragraphs, lists, tables, images, video and hyperlinks
  • The <div> containers that structure the page

Elements in the head section

  • Page title - <title>Home page</title> - displayed in the browser tab and used by search engines.
  • Attach external stylesheets - <link rel="stylesheet" href="styles/main.css"> - using a relative file path. Where several stylesheets are attached, the hierarchy matters: the one listed last is applied last and therefore wins.
  • Metatags, with the appropriate name and content attributes:
    • charset - defines the character set, so accented and non-Latin characters display correctly
    • description - a summary of the page, often shown by search engines in their results
    • keywords - words a search engine may index the page under
    • author - who wrote the page
    • viewport - makes the page display correctly on all devices, including phones and tablets
  • Default target window - <base target="_blank"> sets where every link on the page opens unless a link says otherwise.

Content in the body section

Text elements

  • Apply tags to display pre-defined styles: <h1>, <h2>, <h3>, <p> and <li>.
  • Lists are built with <ul> for an unordered (bulleted) list and <ol> for an ordered (numbered) list, each containing <li> items.

Tables

  • Insert a table with <table>, containing table rows <tr>, table headers <th> and table data <td>.
  • Use table attributes to meet the needs of the audience:
    • colspan and rowspan to make a cell span more than one column or row
    • table and cell sizes set in pixels or % values - a percentage lets the table resize with the window
    • styles and classes applied to the table, rows and cells
  • Why tables are used: to structure and position elements on a page in a predictable grid, so that text, images and other content line up consistently in every browser - as well as to display tabular data.

Objects

  • Images - <img src="logo.png" alt="School logo" width="200">. Set the size, keep the aspect ratio unless told otherwise, and always give alternate text so the image is described if it cannot load and can be read by screen readers.
  • Sound clips and video, with attributes to display controls, remove controls or autoplay, and to adjust the size and aspect ratio.
  • The <div> tag - a container used to group content so that styles and classes can be applied to a whole block at once.
  • Classes applied to elements - <p class="intro"> - so that a named set of styles can be used on any element, any number of times.

Bookmarks, anchors and hyperlinks

A bookmark is a named place within a web page, created by giving an element an id attribute: <h2 id="top">. An anchor is the <a> element that creates a hyperlink; its function is to link from one point to another. A hyperlink's function is to take the visitor to another location when it is clicked.

Create hyperlinks from text and from images to:

  • A bookmark on the same page - <a href="#top">Back to top</a>
  • Other locally stored web pages - <a href="contact.htm">Contact</a>
  • A website, using the URL - <a href="https://www.example.com">Example</a>
  • Send mail to a specified email address - <a href="mailto:info@example.com">Email us</a>
  • Open in a specified location using the target attribute: the same window (_self), a new window (_blank), or a window named as specified (target="results")

Relative and absolute file paths

Relative file path
  • Describes where a file is in relation to the current page - images/logo.png or ../index.htm
  • Still works when the whole site is moved or uploaded to a web server
  • Must be used for links to locally saved web pages and objects, and for attached stylesheets
Absolute file path
  • Gives the full location from the root of a particular computer - C:/Users/Ann/site/images/logo.png
  • Must not be used for local pages or objects: that folder only exists on the author's computer, so every link would break as soon as the site was uploaded or opened on any other machine
  • A full URL to an external website is the one acceptable use
Check your understanding
Explain why a stylesheet must be attached with a relative file path.
A relative path describes the stylesheet's position in relation to the web page, so it still resolves correctly when the whole site is uploaded to a web server or copied to another computer. An absolute path points to a folder that exists only on the author's machine, so the stylesheet would not be found and the page would lose all its formatting.
State the function of the viewport metatag and of the charset metatag.
The viewport metatag makes the page display correctly on all devices, scaling it for phones and tablets rather than showing a shrunken desktop layout. The charset metatag defines the character set so that accented and non-Latin characters are displayed correctly.
Why are tables used to structure elements within a web page?
They provide a predictable grid in which text, images and other content can be positioned and aligned consistently, so the layout holds together in the same way in different browsers and at different window sizes.
21.3

Use Stylesheets (CSS)

Attached stylesheets and inline styles

Attached (external) stylesheet
  • A separate .css file linked from the head of the page
  • One file formats the whole website, so the style is consistent and a change is made once
  • Keeps the HTML short and readable, and the file is cached so pages load faster
Inline style attribute
  • Written inside the element itself: <p style="color:red;">
  • Affects that one element only
  • Useful for a single exception, but it mixes presentation into the content layer and must be changed everywhere if the design changes

Hierarchy - which style wins

  • Styles cascade: where rules conflict, the one applied last or most specifically is used.
  • An inline style attribute overrides any attached stylesheet.
  • Where several stylesheets are attached, the one linked last in the head section overrides those linked before it.
  • A class applied to an element overrides a generic style for that element.

Creating styles and classes

A style created for a tag (such as h1) is applied automatically to every occurrence of that tag. A class is a named set of rules, written with a full stop before the name, that is applied only where it is called by the class attribute - and it can be used on different kinds of element.

Create external styles to be tagged in a web page

  • Styles for h1, h2, h3, p and li.
  • Styles for lists - both ordered and unordered.

Properties you must be able to set, in both generic styles and classes

  • Background properties - colour and images
  • Font properties - font family, size, colour, alignment, bold and italic
  • Table, table row, table header and table data properties:
    • size
    • background colour
    • horizontal and vertical alignment
    • spacing and padding
    • borders - including collapsed, colour, thickness and visible/invisible

Comments and saving

  • Attach comments to an external stylesheet with /* ... */ - used to state the author, the date and what each block of rules does, so the sheet can be maintained later.
  • Save styles in cascading stylesheet format - a plain text file with a .css extension.
Example of the two together
h1 { font-family: Arial, sans-serif; font-size: 32pt; color: #003366; text-align: center; }
.warning { background-color: #ffe0e0; color: #900; font-weight: bold; }
The h1 style applies to every <h1> automatically; the .warning class applies only where class="warning" is written, and can be used on a paragraph, a table cell or a div.
Check your understanding
State two differences between a style and a class.
A style is created for a tag and is applied automatically to every occurrence of that tag; a class is given a name and is applied only where it is called with the class attribute. A class can also be applied to different types of element, while a tag style only affects that one tag.
Three stylesheets are attached to a page and all set a different colour for h1. Which colour is used?
The colour from the stylesheet attached last in the head section, because later rules override earlier ones in the cascade. An inline style attribute on the <h1> itself would override all three.
Give two advantages of an attached stylesheet over inline styles.
One stylesheet formats every page of the site, so the appearance is consistent and a design change is made once in one file instead of in every element. It also keeps the HTML short and readable by separating the presentation layer from the content layer, and the cached file makes pages load faster.
Web authoring checklist
  • I can name the three web development layers and say what each does and which language it uses.
  • I can state the purpose of the head and body sections.
  • I can insert a page title, attach external stylesheets in the correct hierarchy with relative paths, write metatags for charset, description, keywords, author and viewport, and set a default target window.
  • I can build tables with table headers, rows and data, span cells across rows and columns, and set sizes in pixels or percentages.
  • I can explain why tables are used to structure a page.
  • I can insert text, images, sound and video with size, aspect ratio, alternate text and control attributes.
  • I can use div tags and apply classes and styles to elements.
  • I can create bookmarks with id attributes and hyperlinks from text and images to bookmarks, local pages, URLs and email addresses, opening in a specified window.
  • I can explain relative and absolute file paths and why absolute paths must not be used for local links.
  • I can write external styles for h1, h2, h3, p and li, create classes, and set background, font, table, border, spacing and padding properties.
  • I can explain the hierarchy of attached stylesheets and inline styles, the difference between a style and a class, add comments, and save in .css format.
